# ADR 0006: Сохранение реестра сервера при неизвестном статусе процесса

## Context

D01 (2026-09-16; `spec.md` §14, `manifest.md`: D01/R12/R22) фиксирует конфликт: неизвестный статус процесса не означает его отсутствие.
Прежний fallback ADR 0002 допускает новый сервер при недоступном process discovery и принимает duplicate server как компромисс.

## Decision

Неизвестный статус записанного процесса не является основанием для нового `Popen`, смены порта, перезаписи PID record или завершения процесса. Если записанный сервер отвечает, а его командную строку проверить нельзя, helper обновляет snapshot, сохраняет процесс и PID record и возвращает явное предупреждение без утверждений «наш», «жив» или «готов». Если при неизвестном статусе HTTP-проверка кратко завершается по timeout, helper также не объявляет процесс умершим. Управляемый повторный запуск допускается после положительно доказанного отсутствия процесса или устаревшего PID.

Контракты `cmdline(pid) -> str` и `serve(state) -> str` сохраняются. При необходимости различения статуса используется минимальный внутренний шов без новой production dependency. Ни один process probe не завершает процесс; Windows `os.kill(pid, 0)` не применяется. Известные чужие и незаписанные процессы не завершаются.

Этот ADR частично заменяет (`supersedes`) ADR 0002 `0002-safe-cross-platform-dashboard-server-lifecycle.md` только в части разрешения нового запуска по пустому результату недоступного process discovery для записанного сервера и принятия возможного duplicate server как этого компромисса. Подтверждённое переиспользование собственного сервера, привязка к `127.0.0.1`, отделённый скрытый запуск, ограничения finished/SSH/CI и очистка неудачно запущенного собственного `Popen` остаются прежними. ADR 0002 не переписывается.

## Why

Рассмотренная и отвергнутая альтернатива — прежний fallback: считать недоступный process query пустым результатом и запускать сервер на новом порту. По зафиксированному в §14 случаю он скрывает неопределённость под видом отсутствующего процесса и накапливает работающие helper copies. Сохранение реестра и честное предупреждение выбираются вместо этого компромисса: отсутствие разрешения на запрос сведений не становится разрешением создать дубликат или затронуть чужой процесс.

## Consequences

Цена выбора — ограниченное автоматическое восстановление: при недоступном query и кратком HTTP timeout неизвестное состояние сохраняется до положительного доказательства отсутствия процесса или устаревшего PID. Snapshot остаётся доступным, но предупреждение не подтверждает владение сервером.

Критерии относятся к T06; статус D01 `done` в `manifest.md` ограничен проверенными швами. Этот ADR фиксирует решение, не проверяет реализацию, не подтверждает реальную очистку процессов или все ОС и не является release GO.
