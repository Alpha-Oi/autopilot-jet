# ADR 0002: Safe cross-platform dashboard server lifecycle

## Context

`skills/autopilot/tools/sync.py` управляет локальным сервером дашборда, но Unix-команда `ps` недоступна на Windows. Ошибка определения процесса не должна приводить ни к `WinError 2`, ни к завершению чужого процесса, ни к потере file/snapshot fallback.

## Decision

Скрыть платформенные различия за `cmdline(pid)` и `iter_processes()`: POSIX использует `ps`, Windows — доступный системный запрос без shell interpolation. Недоступный механизм возвращает пустой результат и безопасно разрешает запуск нового локального сервера. Процесс запускается с `start_new_session=True` на POSIX и со скрытым окном и новой process group на Windows. Сервер привязывается только к `127.0.0.1`; PID признаётся принадлежащим Autopilot лишь при совпадении ожидаемой command line.

## Why

Проверка владения по одному PID недостаточна: PID может быть повторно использован другим процессом. Платформенный адаптер локализует различия ОС, а fail-safe поведение сохраняет работоспособность синхронизации даже без API перечисления процессов.

## Consequences

Повторный запуск может переиспользовать подтверждённый живой сервер или свободный старый порт, но не завершает неподтверждённые процессы. В SSH/CI сервер не поднимается, после завершения прогона не запускается заново, а при ошибке запуска остаётся snapshot fallback. Пустой результат process discovery может породить новый локальный сервер вместо переиспользования существующего, что принято как более безопасный компромисс.
