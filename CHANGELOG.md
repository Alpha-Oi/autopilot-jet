## [Unreleased]

### Исправлено

- Русская буква в пути на Windows плодила серверы страницы прогресса (третий пробный прогон навыка, 2026-10-06, настоящий компьютер: Windows, имя пользователя `а`, Python 3.14). `sync.py` спрашивает у PowerShell строку запуска записанного сервера и сверяет `--directory` с каталогом прогона. PowerShell на русской Windows печатает в кодовой странице консоли 866, Python читал вывод как cp1251 (оба значения сняты на той машине), буква портилась, путь не совпадал, сервер считался чужим, и каждая синхронизация поднимала новый: к концу прогона работало семь серверов на разных портах, а `serve.pid` помнил только последний, поэтому остановка в конце фазы 8 их не доставала, а `serve.log` держал открытым старую папку. Теперь строка запуска (`cmdline()` и `iter_processes()`) едет из PowerShell как base64 от UTF-8, чистый ASCII, и раскодируется в Python; посторонний текст рядом или неверная кодировка дают пустую строку, а не наполовину разобранную. 18 тестов в `tests/test_windows_cyrillic.py` (в том числе порча буквы 866 → cp1251, воспроизведённая вручную, и случай «записанный сервер жив, каталог с русской буквой, второй не нужен»), десять нарочных поломок краснят тесты (два пережили первую версию, оба усилены); два прежних теста в `tests/test_sync.py` переведены на новый формат ответа. Предел: ответ PowerShell подставлен в тестах, настоящий запрос на Windows гоняет `tests/test_native_runtime.py` в CI на windows-latest, но русской Windows с кодовой страницей 866 в CI нет; починены оба места, где путь приходит из PowerShell, остальные запросы путей не печатают. Остальные находки того же прогона (три странности страницы прогресса, README про Python) разбираются отдельно.

- Запись, которую страница прогресса не может прочесть, перестала выглядеть как данные (третий пробный прогон навыка, 2026-10-06, настоящий `state.js` лежит в `tests/data/pilot3_state.json`). Три расхождения между тем, что записал агент, и тем, что читает страница. (1) Шесть этапов закрыты как `done` с `finishedAt`, но без `startedAt`: страница писала «не начат» рядом с зелёной точкой, а счётчик говорил «8 из 8 этапов пройдено». (2) Итог слепой приёмки записан как `{verdict, drift}`, а страница читала `{matched, checked, mismatches}` (форма `blind` в инструкциях нигде описана не была): вышло «/ требований подтверждено» без чисел и «Расхождений нет». (3) `tests` записан строкой «12 passed», `fmtTests` строку читал, а плитка «Тесты» нет и осталась пустой. Что сделано: `sync.py` (`audit_shapes`) называет закрытый без `startedAt` этап и `blind` без чисел или списка (строку в `tests` не называет: она допустима, так писали раньше); форма `blind` и правило «этап, который не шёл, `skipped` с примечанием, а не `done`» записаны в `phases/7-instruments.md`, `phases/8-final.md`, `phases/5-subagents.md`; страница не утверждает того, чего нет в записи (прочерк вместо «не начат» у пройденного этапа, без чисел нет «N / M», без списка нет «Расхождений нет», плитка читает и строку). В `README.md` записано, что нужен Python 3.11+ с командой `python3` и как его поставить на Windows (на живом прогоне Python у владельца не стоял, а README обещал «больше ничего»). 26 тестов (17 в `tests/test_pilot3_state_shapes.py`, 9 в `tests/test_dashboard.py`), шестнадцать нарочных поломок краснят тесты. Предел: что агент в следующем прогоне пишет эти поля верно, остаётся инструкцией, тест видит только записанное и называет отклонение; один прогон, один проект.
